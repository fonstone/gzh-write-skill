# 多平台改写（小红书 / 抖音口播）

用户说"改写成小红书""做成抖音口播稿""一稿多发"时使用。从最近一篇成稿（或用户指定的稿）改写，**不覆盖原稿**，产出独立平台稿。

## 铁律

1. **保事实，不保句式**：数字、引语、结论只能来自原稿或原稿的 `sources.yaml`，不新增未经核验的断言。
2. **独立成稿**：输出到 `{skill_dir}/output/<slug>-xiaohongshu.md` / `-douyin.md`，原稿不动。
3. **平台归平台**：不把公众号排版语法（`:::callout` 等）带入平台稿；纯文本 + 必要 markdown。
4. 改写后对平台稿重跑 `python3 {skill_dir}/scripts/check_prose.py <平台稿>`（去 AI 味规则同样适用）。

## 小红书图文

| 要素 | 规格 |
|------|------|
| 标题 | ≤20 字，口语化，可带 1 个 emoji；放在第一行 |
| 正文 | 300-800 字；开头 2 行内给钩子（痛点/结果前置） |
| 结构 | 分点或短段（每段 ≤3 行）；小标题可用"· "引导 |
| 图片建议 | 3-6 张：封面 + 要点卡 + 数据图；只给拍摄/制作建议，不生图 |
| 标签 | 5-10 个 `#话题`，与内容相关，不堆砌 |

## 抖音口播稿

| 要素 | 规格 |
|------|------|
| 时长 | 30-60 秒（正文 ≈150-300 字，按 5 字/秒） |
| 开场 | 前 3 秒钩子：一个反常识结论 / 一个具体数字 / 一个直接问题 |
| 语言 | 短句、口语化、可直接念；避免书面连词与括号注释 |
| 结构 | 钩子 → 1 个铺垫 → 1-2 个要点（各带数字或例子）→ 互动收尾 |
| 标注 | 用 `[停顿]`（如需强调）与 `（字幕：…）` 标注关键句 |

## 流程

1. 读原稿 + `sources.yaml`（存在时），圈出可迁移的核心事实 3-5 条。
2. 按平台规格改写；标题给 2 个备选。
3. 跑 `check_prose.py` 清零失败项。
4. 交付时说明：平台稿路径、图片/拍摄建议、与原稿的差异点（如"删掉了 X 章节，因为平台不适合"）。
